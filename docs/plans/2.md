# Plan: Rewrite Backend and CLI in Go

**Issue**: #2
**Status**: IN PROGRESS (Phase 1 complete, starting Phase 2)
**Components**: backend, mcp-server, cli, shared, infra, docs

## Summary

Complete rewrite of the backend API server, MCP server, and CLI from Node.js/TypeScript/Bash to Go. This is a full replacement (not incremental migration) since the project is in early development.

**Key architectural decision**: OpenAPI-first approach. The API specification serves as the single source of truth for:
- Backend handler contracts
- CLI client generation
- API documentation

## Rationale

- Team familiarity with Go from other projects
- Performance, type safety, memory safety
- Better libraries for OAuth and Google integration
- OpenAPI enables code generation and self-documenting API
- Single-binary CLI with better UX (completion, validation)
- Reference implementation available: `../timesheet-app/docs/v2/mcp-implementation.md`

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| API contract breaks | OpenAPI spec is single source of truth; generate code from it |
| SQLite compatibility | Use same schema, test migrations |
| MCP protocol issues | Follow timesheet-app reference closely |
| Frontend breaks | TypeScript types generated from same OpenAPI spec |
| CLI behavior changes | Match all bash CLI flags exactly; run side-by-side tests |
| OpenAPI spec drift | Lint spec in CI; generate code on every build |
